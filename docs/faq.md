# FAQs
1. Why did you patch tools like ASB? 
    To evaluate each tool at its best, within its own idiosyncratic design, without altering that design or its code base. I patched only what was needed to run and measure the tool in our environment, while the benchmark and the design choices made by the developers stayed intact. A patch could touch portability (the conda fallback), configuration (a local judge model), instrumentation (the per-task duration column), robustness (the request timeout and the crash on malformed plan steps), or a subtle bug in a mechanism the tool already intended. It could not touch the tasks, prompts, data, or scoring, and it could not accommodate a particular model. 
    For example, I added the "User: please regenerate the plan" turn because a plan retry is already part of ASB's design and only its implementation, which appends "Assistant" instead of "User" as the last message, did not work. By contrast, ASB's plain-text response, which does not ensure that models always return valid JSON, is a design choice of its own that works as intended, so I did not patch or modify it, and the same goes for the invalid example JSON inside its plan prompt, even though both cost `qwen3-coder:30b` every task.
